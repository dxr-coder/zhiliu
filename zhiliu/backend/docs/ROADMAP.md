# AI 智能客服系统 — 版本演进路线图

> 每个版本不是"加功能"，是**解锁一个新能力维度**。
> 项目名称：SmartFlow — AI 智能客服平台

---

## 产品定位

**一句话**：帮企业解决"内部知识找不到、客服效率低"的问题。

用户（企业员工/客户）提问 → AI 基于企业私有知识库准确回答 → 复杂问题自动创建工单 → 需要时无缝转人工。

**不是聊天机器人 demo，是完整的客服业务系统。**

## v2：能用 — 多用户 + 权限 + 业务闭环

**一句话：多人能用，有完整的客服业务流程。**

### 核心概念

| 概念 | 为什么重要 |
|------|-----------|
| JWT 认证 | 生产系统必须知道"谁在用" |
| 密码哈希（bcrypt） | 密码不能明文存数据库 |
| RBAC 权限模型 | 不同角色看不同内容 |
| SSE 流式输出 | LLM 回答是逐字生成的，用户不想等 5 秒 |
| PDF 解析 | 实际文档大多是 PDF |
| Redis 缓存 | 省 Token 费用，加速重复问题 |

### 功能清单

**用户系统**
- 注册 / 登录（JWT，access_token + refresh_token）
- 三级角色：管理员 / 客服 / 普通用户
- 权限隔离：管理员看全部，客服看分配的对话，用户只看自己的

**工单系统**
- 用户发起工单（退款/投诉/咨询）
- AI 自动分类工单类型
- 状态流转：待处理 → 处理中 → 已解决 → 已关闭
- 超时未处理自动提醒

**转人工机制**
- AI 连续 2 次回答"不确定" → 建议转人工
- 用户主动说"转人工" → 触发转接
- 人工客服接入后 AI 退场

**其他**
- SSE 流式输出（回答逐字显示）
- PDF 文档上传 + 解析
- 语义缓存（Redis）
- 使用配额（普通用户每天 50 次）

### 里程碑
- M1：JWT 认证（注册/登录/Token 刷新）
- M2：用户角色 + 权限中间件
- M3：工单系统（创建/查询/状态流转）
- M4：转人工机制
- M5：PDF 解析 + SSE 流式输出 + Redis 缓存

## v4：能强 — 多 Agent 协作 + 智能决策

**一句话：复杂问题多 Agent 协作解决，系统能自主决策。**

### 核心概念

| 概念 | 为什么重要 |
|------|-----------|
| Multi-Agent | 单 Agent 解决不了复杂任务 |
| LangGraph 状态机 | 复杂工作流编排 |
| 插件系统 | 可扩展，不改核心代码加新功能 |
| 自动摘要 | 长对话压缩 token |

### 功能清单

**多 Agent 协作引擎**
- 意图分类 Agent：判断用户意图
- 知识库 Agent：专门做 RAG 检索和回答
- 工单 Agent：专门处理工单创建/查询/流转
- Function Agent：7 个工具（查假期/报销/会议室/设备等）
- 专科 Agent：HR / IT / 财务 / FAQ

**插件系统**
- 新工具只需写一个文件，自动注册
- 内置插件：计算器/网页搜索/SQL 查询

**其他**
- 对话自动摘要（长对话压缩 token）
- 知识库版本管理
- A/B 测试框架

### 里程碑
- M1：意图分类 Agent
- M2：多 Agent 路由 + 协调
- M3：插件系统 + 工具自动注册
- M4：Function Calling Agent
- M5：自动摘要 + 知识库版本管理

## v6：工程扎实 — 安全 + 测试 + 可观测 + 文档

**一句话：从"功能全"升级到"工程扎实"。**

### 功能清单

**安全加固**
- JWT_SECRET fail-fast（启动时检查，没配直接崩）
- 登录/注册 IP 限流（5次/分 + 20次/天）
- 缓存 user_id 隔离（防跨用户泄漏）
- IDOR 防护（save_message 前置所有权查询）
- refresh token 轮换 + 复用检测

**测试地基**
- pytest 45 个用例，零外部依赖（fakeredis + FakeDB）
- 覆盖：auth 轮换 / 限流边界 / 熔断三态 / RRF 公式 / 审批权限 / 缓存隔离

**可观测性**
- 结构化 JSON 日志（自动注入 trace_id）
- Prometheus 7 个指标（HTTP/LLM/熔断/缓存/限流）
- Token 用量回填（usage → ContextVar → middleware → DB）

**性能优化**
- 语义缓存 L2 归一化（点积 → 余弦）
- executemany 替代循环插入
- 文件上传 1MB 分块流式落盘（峰值内存 300MB → 1MB）
- JWT role claim（每请求 0 次 DB 查询）

**文档**
- README（架构图 + 快速启动）
- ERD（28 张表全景）
- ARCHITECTURE（时序图 + 状态机）
- TRADEOFFS（10 项技术取舍）

### 里程碑
- M1：安全加固（7 项修复）
- M2：测试地基（45 个用例）
- M3：可观测性（日志 + 指标 + Trace）
- M4：性能 + 代码质量
- M5：文档终态
